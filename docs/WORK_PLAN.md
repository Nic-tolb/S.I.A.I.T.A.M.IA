## Team rules

- Everything reaches `develop` through a **Pull Request** reviewed by another member. Only stable versions reach `main`.
- Short-lived branches: one PR per feature, not one giant PR per member.
- Frequent commits with a prefix, in English: `feat(incidents): ...`, `fix(rag): ...`, `docs(report): ...`, `chore(docker): ...`
- Everyone works in their own view files (`js/views/<view>.js`). Changes to shared files (`index.html`, `styles.css`, `docker-compose.yml`, `01_schema.sql`) go in small PRs, announced to the team.
- **Language:** code, comments and docs in English; user-visible frontend text in Spanish.
- **Final presentation:** each member presents their own modules.
